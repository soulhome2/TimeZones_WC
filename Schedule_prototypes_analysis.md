# Time Schedules (Временные зоны) — анализ прототипов и обоснование финального варианта

**Продукт:** ITV/Axxon — Интеллект X / Axxon One / Axxon Next
**Раздел:** WEB-конфигуратор → Временные зоны / Time schedules
**Дата:** 08.09.2026
**Артефакты:** `schedule_v3.html` (финальный прототип), этот файл (анализ)

---

## 0. Терминологическая проблема, которую надо решить на уровне продукта

В десктопном конфигураторе раздел называется **«Временные зоны» / "Time zones"**, хотя речь идёт
не о UTC-смещениях, а о **недельных расписаниях активности**. В англоязычной документации Axxon One
1.0/2.0 тот же экран уже называется **"Time Schedules"**, а в 3.0 вернулись к "Time zones"
([Axxon One 3.0 — Time zones](https://docs.axxonsoft.com/confluence/spaces/ONE2025/pages/314537999/Time+zones),
[Axxon One 1.0 — Creating schedules](https://docs.axxonsoft.com/confluence/spaces/one1en/pages/226952566/Creating+schedules)).

Прототип 2 (веб) использует URL `#/time_zones`, но заголовок панели — «Временные расписания».
Это уже расхождение внутри одного экрана.

**Рекомендация:** в web-конфигураторе закрепить название **Time schedules / Временные расписания**
и добавить подпись-дисклеймер («Reusable weekly patterns — *not* UTC offsets»), чтобы снять
путаницу у интеграторов. В `schedule_v3.html` это сделано.

### Вариант 1 — Figma-прототип (первоначальный)

**Источник:** [Figma — Веб-конфигуратор, node 790-266790](https://www.figma.com/design/jXtHpJfs2DJKMhBNja3AdO/%D0%92%D0%B5%D0%B1-%D0%BA%D0%BE%D0%BD%D1%84%D0%B8%D0%B3%D1%83%D1%80%D0%B0%D1%82%D0%BE%D1%80?node-id=790-266790&p=f&t=k2pUZaF14mvaUyva-0)

> ⚠️ **Ограничение анализа.** Файл Figma закрыт авторизацией, программный доступ к макету получить
> не удалось. Поэтому вариант 1 оценивается по **функциональной модели десктопного продукта**,
> которую он воспроизводит (официальная документация Axxon One / Axxon Next / Axxon PSIM), и по тем
> элементам, которые унаследованы двумя сгенерированными прототипами. Если в макете есть блоки,
> отсутствующие в этом описании, их нужно сверить отдельно — раздел 6 содержит чек-лист.

**Функциональная модель (десктоп, воспроизводимая макетом):**

| Возможность | Описание |
|---|---|
| Список зон | «Список временных зон» + поле имени + кнопка добавления/удаления |
| Таблица интервалов | Строки `От` / `До` + **чекбоксы дней недели в той же строке** — один интервал сразу для нескольких дней |
| Ввод времени | Шаг ±1 ч / ±5 мин по двойному клику (наследие desktop) |
| Временная диаграмма | **Только визуализация**, редактирование мышью не предусмотрено |
| Праздники | Чекбокс `Holidays` + отдельная дата + `Period, days` (срабатывание каждые N дней) — Axxon PSIM |
| Переход через полночь | Если «от» > «до», зона покрывает текущий день и часть следующего |
| Комбинации расписаний | Дополнительное расписание корректирует основное в особые дни |
| Применение | `Применить` / `Отмена` |

**Плюсы**

- Единственный вариант, где **корректно отражена реальная доменная модель**: интервал принадлежит
  набору дней, а не одному дню; есть даты-исключения, периодичность в N днях, признак праздников.
- Табличный ввод точен и предсказуем, удобен для аудита и для скринридеров.
- Прямая преемственность с десктопом → нулевая стоимость переобучения инженеров.

**Минусы**

- Диаграмма пассивна: нельзя нарисовать или перетащить интервал — главный UX-разрыв 2026 года.
- Ввод времени кнопками ±5 мин — самая медленная из возможных механик.
- Нет обзора «где используется», нет копирования дней, нет шаблонов, нет подсчёта часов.
- Экран плотный и «инженерный»: сложно оценить покрытие недели одним взглядом.

### Вариант 2 — сгенерированный прототип №1: `Time Schedule.html`

Технически это **упакованный артефакт на внутреннем DSL** (`<x-dc>` + `DCLogic` + компоненты
`OnePsimUi.*`), собранный поверх **штатной дизайн-системы Axxon One** (CSS-токены `--one-color-*`,
`--one-space-*`, Inter / Roboto Mono, светлая и тёмная схемы). То есть визуально это самый
«родной» для продукта вариант, но он не является обычным HTML/JS.

**Что реализовано**

| Блок | Детали |
|---|---|
| Сайдбар | Поиск, `+ New schedule`, список с **мини-превью недели** (7 полосок-градиентов), метаданные `N h/wk · N uses`, точка «активно сейчас» |
| Шапка | Имя, пилюля `Coverage: N h / week`, пилюля `Active now / Inactive now`, `Delete` / `Save` / `Cancel` |
| Шаблоны | 4 пресета (Business 9–18, Nights 22–06, Weekends, 24/7) **с мини-диаграммой на кнопке** |
| Область действия | Пресеты применяются либо ко всей неделе, либо к **отмеченным чекбоксами дням** |
| Подтверждения | Модальный `alertdialog` перед любым разрушающим действием |
| Сетка | 7 строк, drag блока, resize за края, **snap 15 мин**, double-click = новый интервал |
| Меню дня | `Clear day` / `Fill full day (24h)` / `Copy to…` (мультивыбор дней-чипов) |
| Инспектор интервала | `Start` / `End` (`input type=time`), `Duration`, `Copy to…`, `Delete interval` |
| Мультидневный режим | `Copy from…`, `Clear checked days`, `Uncheck all`, приглушение невыбранных строк |
| Уведомления | `MessageBar` success / info / warning; при удалении — предупреждение «использовалось в N местах» |

**Плюсы**

- Лучшая **информационная архитектура списка**: превью недели + часы + счётчик использований
  позволяют выбрать нужное расписание, не открывая его.
- Мышиное редактирование (drag / resize / snap) — то, чего нет в десктопе.
- Продуманная **область действия массовых операций** (чекбоксы дней) и защита подтверждениями.
- Единственный вариант, который **честно говорит о последствиях удаления**.
- Полностью на дизайн-токенах → бесплатно получает тёмную тему и консистентность с остальным
  конфигуратором.

**Минусы**

- 🔴 **Мёртвый код: главные доменные функции построены, но не отрендерены.** В логике есть
  `seedExceptions()`, `buildExceptionsVM()` (даты + режимы `Closed all day` / `Same as Sunday` /
  `Custom hours`) и `buildUsedInVM()` (Roles / Macros / Export / Replication), а также `NAV_ITEMS`, —
  но в шаблоне нет ни аккордеона исключений, ни панели «где используется», ни навигации. Прототип
  показывает меньше, чем умеет.
- 🔴 Нет **режима рисования** (draw/erase) — интервал можно только добавить двойным кликом и потом
  тянуть; «нарисовать» интервал протяжкой нельзя.
- 🔴 Нет **undo/redo** — при drag-редактировании это критично.
- 🔴 Нет **интервалов через полночь**: `end` жёстко ограничен 1440, «22:00–06:00» смоделировано как
  два разных интервала в одном дне (`22:00–24:00` + `00:00–06:00`), что расходится и с доменной
  моделью, и с API.
- Нет часов по каждому дню (только суммарно за неделю), нет маркера «сейчас» на сетке.
- Шаг привязки зафиксирован на 15 мин, выбрать нельзя.
- Нет цикличных интервалов, срока действия, периодичности в N днях.
- `pattern.weekend` и `pattern.always` дублируют друг друга — пресеты «Weekends» и «24/7» отличаются
  только набором дней; набор шаблонов беднее реальных сценариев (нет двух смен, нет «нерабочее время»).

### Вариант 3 — сгенерированный прототип №2 (скриншот, `screenshot-1.png`)

Работающая страница `localhost:3000/configurator/#/time_zones`, русский интерфейс, светлая тема,
акцент `#0070e4` — та же дизайн-система. В DevTools на скриншоте видно **реальный payload API**.

**Что реализовано**

| Блок | Детали |
|---|---|
| Навигация | Полные табы конфигуратора: Устройства · Группы · Детекторы · Архивы · Роли и пользователи · **Временные зоны** · Макрокоманды · Системный журнал · Настройки |
| Сайдбар | «Временные расписания», `+`, поиск, список с метаданными («7 ч в сутки», «73 ч в неделю») |
| Шапка | «Название расписания», **«Итого в неделю 72 ч 48 мин»**, `Отмена` / `Сохранить` |
| Тулбар | **`Рисовать` / `Стирать`**, **undo / redo**, **`Шаг`: 15 мин / 30 мин / 1 ч**, `Шаблоны ▾`, `Очистить неделю` |
| Сетка | Часы 00–23, 7 строк (Понедельник…Воскресенье), **сумма часов по каждому дню справа** (17 h, 17 h, 21 h, 0 h…), выделение активной строки рамкой |
| Подсказка | «Нажмите на интервал для редактирования. Перетаскивайте интервалы для перемещения.» |
| Правая панель дня | «Воскресенье», «Интервалов: 2 · 17 ч», быстрые кнопки **`Весь день` / `09:00–18:00` / `Очистить`**, список интервалов с полями времени и корзиной, `+ Добавить интервал` |
| Копирование дня | «Копировать этот день» + чекбоксы дней + `Копировать` + `Все дни` |

**API (из вкладки Network — важный вход для модели данных):**

```
modify_intervals: [{ id: "…", added_intervals: [ { start: { hour, minute, second },
                                                   length_seconds, period_seconds } ],
                     modified_intervals: [], removed_intervals: [] }]
```

То есть сервер оперирует не парой «начало–конец», а тройкой
**`start` + `length_seconds` + `period_seconds`**. Это принципиально: длительность может
«переезжать» за полночь, а `period_seconds` открывает **цикличные интервалы** (сработать на N секунд
каждые M секунд) — прямой аналог `Heartbeat interval` у Cycle-rules макросов
([Configuring macros](https://docs.axxonsoft.com/confluence/spaces/one20en/pages/246485017/Configuring+macros)).

**Плюсы**

- 🟢 **Лучшая механика ввода из трёх**: рисование/стирание протяжкой + выбор шага + undo/redo.
  Заполнить неделю здесь быстрее всего.
- 🟢 **Лучшая правая панель**: точные значения интервалов, быстрые заготовки на день, копирование
  дня в выбранные дни — всё в одном месте, без всплывающих меню.
- 🟢 Полезные счётчики: сумма по неделе **и по каждому дню** (`17 h`, `21 h`), «Интервалов: 2».
- 🟢 Встроен в реальную оболочку конфигуратора с навигацией → сразу понятен контекст.
- 🟢 Есть настоящий backend-контракт → меньше риска расхождения прототипа и реализации.

**Минусы**

- В списке расписаний нет превью недели и счётчика использований — расписания различимы только по имени
  (на скриншоте они и называются «11111», что само по себе говорит об отсутствии подсказок к нейминингу).
- Нет панели **«где используется»** и предупреждения при удалении → можно молча сломать запись в архив.
- Нет **дат-исключений и праздников** — прямая потеря функциональности относительно десктопа/PSIM.
- Нет области действия для массовых операций: `Очистить неделю` и `Шаблоны` бьют по всей неделе;
  мультивыбор дней отсутствует (чекбоксы есть только в блоке «Копировать этот день»).
- Нет интервалов через полночь в UI (хотя API это позволяет), нет цикличных интервалов
  (хотя `period_seconds` уже в контракте).
- Нет маркера «сейчас», нет признака «активно сейчас», нет срока действия расписания.
- Нет индикатора несохранённых изменений и защиты при переключении расписания.

## 4. Решение по финальному варианту `schedule_v3.html`

**База — вариант 3** (компоновка, тулбар, правая панель, светлая тема с акцентом `#0070e4`,
оболочка конфигуратора), **дополненная сильными сторонами варианта 2** (превью в списке,
чекбоксы дней, подтверждения, «где используется») **и доменной моделью варианта 1**
(исключения, праздники, периодичность, через полночь). Это минимизирует объём переделок:
переиспользуется уже реализованный экран, а не создаётся новый.

Оформление на CSS-переменных-аналогах токенов `--one-*` из варианта 2 → светлая и тёмная схемы,
типографика Inter / Roboto Mono, те же радиусы и высоты контролов. Один самодостаточный HTML-файл
без внешних зависимостей — открывается двойным кликом и работает офлайн. Язык интерфейса — английский.

### 4.1. Компоновка

```
Верхняя панель: Web Configurator · Devices Groups Detectors Archives Roles&users [Time schedules] Macros Audit log Settings · [Русский ▾] · 24h/12h · ◐
┌── Time schedules (268) ──┬─────────── Editor ────────────────────┬── Day inspector (306) ──┐
│ поиск, + New schedule    │ имя · N h/week · % · Active now · ⚑   │ Monday                  │
│ карточки с превью недели │ Draw|Erase ↶↷ Snap Templates Invert   │ Quick fill              │
│ N h/week · N uses        │ ── сетка 24 ч × 7 дней ──             │ Intervals (from/to/↻/🗑) │
│ ⋯ Duplicate / Delete     │ строка выбора (block | N days)        │ + Add interval          │
│ Import / Export JSON     │ ▸ Used in  ▸ Exceptions  ▸ Advanced   │ Copy Monday to · Merge  │
│                          │ ▸ API payload preview                 │                         │
└──────────────────────────┴───────────────────────────────────────┴─────────────────────────┘
```

### 4.2. Что взято из какого варианта

**Из варианта 3 (база):**
- трёхколоночная компоновка и оболочка конфигуратора с табами;
- `Draw` / `Erase`, undo/redo, `Snap` (расширено до 5/15/30/60 мин), `Templates ▾`, `Clear week`;
- суммы часов по каждому дню в сетке и итог за неделю в шапке;
- правая панель дня: счётчики, `Quick fill`, список интервалов с полями времени и удалением,
  `+ Add interval`, «Copy this day to» с чекбоксами дней.

**Из варианта 2:**
- мини-превью недели, `N h/week · N uses` и точка «активно сейчас» в карточках списка;
- чекбоксы дней в сетке как **область действия** для `Templates` / `Invert` / `Clear`
  (приглушение неотмеченных строк);
- drag блока и resize за края, double-click, меню дня `⋯`;
- модальные подтверждения, тосты, предупреждение об использовании при удалении;
- панель **`Used in`** (ожившая из мёртвого кода);
- аккордеон **`Exceptions & holidays`** (тоже из мёртвого кода, расширен).

**Из варианта 1 / документации:**
- **интервалы через полночь**: `start + length > 24 ч`; продолжение рисуется в следующем дне
  штриховкой `↳` и редактируется из исходного дня;
- **даты-исключения и праздники**: диапазон дат, режим (`Non-working` / `24 hours` /
  `Same as weekday` / `Custom intervals`), повтор ежегодно, комментарий, флаг «применять
  общесерверный список праздников»;
- **периодичность «каждые N дней»** вместо недельной (сменные графики 2/2, 4/4);
- **срок действия** `Valid from` / `Valid to`.

### 4.3. Что добавлено сверх всех трёх (и почему)

| Добавлено | Обоснование |
|---|---|
| **Цикличные интервалы** (`N мин каждые M мин`, штриховка на блоке, ↻ в инспекторе) | `period_seconds` уже в API варианта 3; сценарий «выборочная запись в архив», аналог `Heartbeat interval` в макросах. Единственный способ выразить это без отдельного экрана. |
| **Copy day → Merge / Replace** | В2 и В3 умеют только замену. Merge нужен, когда к базовому дню добавляют смену. |
| **`Invert` (день / отмеченные дни / неделя)** | «Нерабочее время» — один из самых частых сценариев (охрана, автоарм). Без инверсии его рисуют вручную. |
| **Панель `Used in` с разбивкой** Archive recording · Roles · Macros · Video export · Replication | Расписание — разделяемый объект. Без этой панели сужение интервала молча ломает запись в архив. Разбивка соответствует местам использования по документации. |
| **Индикатор `Unsaved changes` + guard при переключении расписания** | В3 позволяет уйти с несохранёнными правками. |
| **Маркер «сейчас» на строке текущего дня + бейдж `TODAY`** | Мгновенный ответ на вопрос «почему сейчас не пишется?». |
| **% покрытия недели** рядом с суммой часов | Проще сравнивать расписания и замечать ошибку вида «покрыто 2%». |
| **Расширенный набор шаблонов (8)** с мини-диаграммой | Добавлены `Extended office`, `Two shifts`, `Non-working hours`, `Cyclic sampling` — реальные сценарии, отсутствовавшие в В2 (4 шаблона, из которых два дублировали друг друга). |
| **Клавиатура**: `Del`, `←`/`→` (сдвиг), `Shift`+`←`/`→` (длительность), `Ctrl+Z` / `Ctrl+Shift+Z`, `Ctrl+S`, `Esc` | Требование доступности и скорости для операторов, работающих с клавиатуры. |
| **Формат 12 / 24 ч** | Локализация под рынки с AM/PM. |
| **Переключатель языка RU / EN** (комбобокс слева от 24h/12h) | Продукт поставляется на два рынка; прототип должен показывать интерфейс в обеих локалях, потому что русские формулировки в 1,3–1,5 раза длиннее английских и ломают вёрстку панелей. Все строки вынесены в словарь `I18N`; русские числительные согласуются по правилам (`1 день / 2 дня / 5 дней`), названия дней имеют падежные формы (`копировать среду`, `перенос со вторника`, `продолжается во вторник`). Демо-данные хранятся ключами, поэтому смена языка переименовывает примеры, но **не** затрагивает то, что переименовал пользователь, и не помечает расписание изменённым. |
| **Тёмная тема** | В дизайн-системе Axxon One тёмная схема — первого класса; токены уже есть. |
| **Импорт / экспорт JSON** | Тиражирование конфигурации между серверами и площадками. |
| **`API payload preview`** | Прототип превращается в исполняемую спецификацию: разработчик сразу видит `added / modified / removed_intervals` с `start`, `length_seconds`, `period_seconds`. Снимает риск расхождения UI и контракта. |
| **Примечание о DST / reference time** | Интервалы хранятся как смещения внутри недели и вычисляются по локальному времени сервера; переход на летнее время сдвигает «настенное» окно. Раньше это нигде не проговаривалось. |

### 4.4. Модель данных прототипа

```js
interval = { id, start, len, cyc }        // минуты от 00:00; start+len > 1440 ⇒ переход через полночь
cyc      = null | { every, on }           // цикл: активен `on` мин каждые `every` мин

schedule = { id, name,
             days: { Mon:[interval], … Sun:[interval] },
             exceptions: [{ from, to, mode, sameAs, iv, yearly, note }],
             validFrom, validTo, repeatDays, useHolidayList, usedIn }
```

Сериализация 1:1 в контракт варианта 3:

```json
{ "start": { "day_of_week": 1, "hour": 9, "minute": 0, "second": 0 },
  "length_seconds": 32400,
  "period_seconds": 604800 }
```

Цикличный интервал: `period_seconds` = длина цикла, `pulse_seconds` = активная часть.
`day_of_week` добавлен, потому что в наблюдаемом payload виден только `hour/minute/second` —
**это пункт для уточнения у backend-команды** (см. раздел 6).

### 4.5. Инварианты и валидация

- Пересекающиеся и соприкасающиеся простые интервалы автоматически сливаются (`normalize`);
  цикличные не сливаются никогда — у них своя семантика.
- Минимальная длина интервала = текущий шаг привязки.
- Стирание режет интервал на части, а не удаляет целиком (`subtract`).
- Часы по дню считаются как «фактически покрытые минуты этого календарного дня»
  (собственные интервалы + перенос с предыдущего дня); недельный итог — сумма длительностей,
  без двойного учёта. Для цикличных учитывается только активная часть цикла.
- Последнее расписание удалить нельзя.

## 5. Как проверить прототип

Открыть `schedule_v3.html` в браузере (Chrome / Edge / Firefox, без сервера).

Сценарии:

1. **Рисование** — `Draw`, протянуть по пустой дорожке Wednesday; протянуть за край блока; перетащить блок; `Erase` и протянуть по середине блока (интервал разрежется на два).
2. **Массовые операции** — отметить чекбоксы Mon–Fri, `Templates ▾ → Two shifts`, подтвердить; затем `Invert`.
3. **Через полночь** — `Templates ▾ → Nights`: в каждом дне появится блок с 22:00 и штрихованное продолжение `↳` до 06:00 в следующем; в инспекторе — «continues to 06:00 on …».
4. **Цикличный интервал** — выбрать расписание `Archive sampling (cyclic)`; блок штрихованный, в строке выбора настраиваются `on` / `every`; сравнить `28 h / week` с 168 h у `24/7`.
5. **Копирование** — открыть Sunday, отметить `Mon–Fri`, сравнить `Merge` и `Replace`.
6. **Безопасность** — изменить что-нибудь (появится `Unsaved changes`), попробовать переключить расписание; затем `Delete` у `Business hours` — в диалоге будет указано число зависимых объектов.
7. **Доменные блоки** — раскрыть `Used in`, `Exceptions & holidays`, `Validity, recurrence & advanced`, `API payload preview`.
8. **Прочее** — `Ctrl+Z` / `Ctrl+Shift+Z`, `24 h / 12 h`, переключатель темы `◐`.

**Продуктовые решения:**

## 7. Приоритизация для реализации

| Приоритет | Что | Почему |
|---|---|---|
| **P0** | Панель `Used in` + предупреждение при удалении | Предотвращает молчаливую поломку записи в архив |
| **P0** | Интервалы через полночь | Регресс относительно десктопа; ночные смены — базовый сценарий |
| **P0** | Индикатор несохранённых изменений + guard | Потеря работы пользователя |
| **P1** | Область действия массовых операций (чекбоксы дней) | `Clear week` без области действия опасен |
| **P1** | Даты-исключения и праздники | Регресс относительно десктопа/PSIM |
| **P1** | Превью недели и счётчик использований в списке | Расписания неразличимы по одному имени |
| **P2** | Цикличные интервалы | API готов, сценарий выборочной записи |
| **P2** | `Invert`, `Merge` при копировании, расширенные шаблоны | Скорость ввода |
| **P2** | Клавиатура, 12/24 ч, тёмная тема | Доступность и локализация |
| **P3** | Срок действия, периодичность N дней | Нишевые, но есть в PSIM |
| **P3** | Импорт / экспорт JSON | Тиражирование конфигураций |
