# Временные зоны / Time schedules — чем прототип v3 отличается от первых двух версий

**Продукт:** ITV/Axxon — Интеллект X / Axxon One / Axxon Next
**Раздел:** WEB-конфигуратор → Временные зоны / Time schedules
**Дата:** 08.09.2026
**Предмет сравнения:** `schedule_v3.html` против двух ранее сгенерированных прототипов

---

## Нумерация версий в этом документе

Чтобы не путаться, ниже используется сквозная нумерация **версий веб-прототипа**:

| Здесь | Артефакт | В файле `Schedule_prototypes_analysis.md` |
|---|---|---|
| **v1** | `Time Schedule.html` — упакованный артефакт на внутреннем DSL (`<x-dc>` + `DCLogic` + `OnePsimUi.*`) | «Вариант 2» |
| **v2** | Работающая страница `localhost:3000/configurator/#/time_zones` (скриншот `screenshot-1.png`) | «Вариант 3» |
| **v3** | `schedule_v3.html` — финальный прототип | «Финальный вариант» |

**Figma-макет** сюда не входит: это не версия веб-прототипа, а **первоисточник доменной модели**
(та же модель, что в десктопном конфигураторе). Он используется как эталон полноты функциональности,
и значительная часть отличий v3 — это как раз возврат того, что v1 и v2 потеряли относительно десктопа.

---

## Коротко: три главных отличия

1. **v3 — первый вариант с полной доменной моделью.** v1 и v2 умели описывать только «интервал внутри
   одних суток». v3 добавляет то, без чего экран не заменяет десктопный: **интервалы через полночь**,
   **цикличные интервалы**, **даты-исключения и праздники**, **срок действия**, **периодичность в N дней**.
2. **v3 объединяет механику ввода v2 с обзорностью v1.** Из v2 взяты рисование/стирание протяжкой,
   undo/redo и выбор шага; из v1 — превью недели в списке, чекбоксы дней как область действия массовых
   операций и предупреждения о последствиях. Раньше приходилось выбирать одно из двух.
3. **v3 — единственный вариант, готовый к сдаче в разработку и к двум рынкам:** предпросмотр payload API,
   переключатель языка RU/EN с полной локализацией, регулируемые панели и постоянная строка состояния.

## 1. Доменная модель интервала — главное отличие

Это расхождение важнее всех UI-улучшений: v1 и v2 физически не могли выразить часть реальных сценариев.

| | v1 `Time Schedule.html` | v2 скриншот | **v3** |
|---|---|---|---|
| Модель | пара «начало–конец», `end` жёстко ≤ 1440 | `start` + `length_seconds` + `period_seconds` (в API) | `{ start, len, cyc:{every,on} }`, `start + len > 1440` = переход через полночь |
| Ночная смена 22:00–06:00 | два отдельных интервала в одном дне (`22:00–24:00` + `00:00–06:00`) | в UI не выражается | один интервал, продолжение рисуется в следующем дне штриховкой `↳` и правится из исходного дня |
| Цикличные интервалы | ⛔ | ⛔ в UI, хотя `period_seconds` **уже в контракте** | ✅ «N мин каждые M мин», штриховка на блоке, ↻ в инспекторе |
| Даты-исключения | 🧩 есть в коде (`seedExceptions`, `buildExceptionsVM`), но **не отрендерены** | ⛔ | ✅ аккордеон: диапазон дат, 4 режима, повтор ежегодно, комментарий |
| Праздники | 🧩 в коде | ⛔ | ✅ флаг «применять общесерверный список праздников» |
| Срок действия | ⛔ | ⛔ | ✅ `Valid from` / `Valid to` |
| Периодичность «каждые N дней» | ⛔ | ⛔ | ✅ для сменных графиков 2/2, 4/4 |

**Почему это критично.** Модель «двух интервалов вместо одного» из v1 расходится и с десктопом,
и с API: сервер получает две записи вместо одной, суммарные часы считаются верно, но при
редактировании ночной смены пользователь правит два объекта, не понимая, что это одна смена.
В v3 модель совпадает с серверной.

## 2. Механика редактирования

| | v1 | v2 | **v3** |
|---|---|---|---|
| Создание интервала | двойной клик, затем растянуть | **рисование протяжкой** | рисование протяжкой + `+ Добавить интервал` + быстрые заготовки |
| Стирание | только удаление блока целиком | **стирание протяжкой** | стирание протяжкой, в том числе поверх существующих блоков (режет их) |
| Перемещение / изменение длины | drag + resize за края | drag (resize за края не подтверждён) | drag + resize за края |
| Шаг привязки | 15 мин, **зафиксирован** | 15 / 30 / 60 мин | **5** / 15 / 30 / 60 мин |
| Undo / Redo | ⛔ | ✅ | ✅ (до 60 шагов, гранулярно: одно перетаскивание = один шаг) |
| Клавиатура | ⛔ | ⛔ | `Del`, `←`/`→` — сдвиг, `Shift`+`←`/`→` — длительность, `Ctrl+Z`, `Ctrl+Shift+Z`, `Ctrl+Y`, `Ctrl+S`, `Esc` |
| Точный ввод времени | `Start`/`End` для одного интервала | таблица интервалов дня | таблица интервалов дня + строка выбранного блока с полями `С`/`По` и длительностью |

**Что изменено сознательно:** в v1 новый интервал создавался двойным кликом, а в v3 двойной клик
**открывает** блок в правой панели. Создание отдано протяжке — это быстрее и не конфликтует
с выделением.

## 3. Массовые операции и область действия

Здесь v1 и v2 были противоположны, и v3 берёт сильную сторону v1.

| | v1 | v2 | **v3** |
|---|---|---|---|
| Область действия массовых операций | ✅ чекбоксы дней; пресеты бьют по отмеченным | ⛔ `Очистить неделю` и `Шаблоны` бьют по **всей неделе** | ✅ чекбоксы дней + приглушение неотмеченных строк + подсказка в тулбаре, на что подействует кнопка |
| Копирование дня — замена | ✅ | ✅ | ✅ |
| Копирование дня — **добавление (merge)** | ⛔ | ⛔ | ✅ нужно, когда к базовому дню дописывают смену |
| Копирование одного интервала | ✅ | ⛔ | ✅ в выбранный день или во все остальные |
| Инверсия дня / недели | ⛔ | ⛔ | ✅ «нерабочее время» одним нажатием вместо ручной обводки |
| Шаблоны | 4 пресета, два из которых дублируют друг друга (`weekend` и `always` отличаются только набором дней) | есть, состав по скриншоту не полон | **8 пресетов** с мини-диаграммой: рабочие часы, расширенный офис, две смены, ночи, нерабочее время, выходные, 24/7, цикличная выборка |

## 6. Локализация — полностью новое в v3

Ни v1, ни v2 не имели переключения языка: v1 был только английским, v2 — только русским.

- **Комбобокс RU / EN** в правом верхнем углу, слева от переключателя 24h/12h.
- Все **274 строки интерфейса** вынесены в словарь `I18N`; состав ключей в обеих локалях
  идентичен (проверяется автоматически).
- **Русские числительные согласуются**: «1 день / 2 дня / 5 дней», «21 место», «11 интервалов».
- **Падежные формы дней недели** — иначе получались фразы вида «перенос с воскресенье».
  Заведены винительный («Копировать **среду** в»), родительный с предлогом («перенос **со вторника**»)
  и предложный («продолжается **во вторник**»).
- **Демо-данные хранятся ключами**, а не готовым текстом: смена языка переименовывает примеры,
  но не затрагивает то, что переименовал пользователь, не помечает расписание изменённым
  и не ломает историю undo/redo.
- **Формат 12 / 24 ч** — тоже отсутствовал в обеих версиях.

## 7. Обратная связь и строка состояния — новое в v3

| | v1 | v2 | **v3** |
|---|---|---|---|
| Способ уведомления | `MessageBar` success / info / warning | всплывающие уведомления в правом верхнем углу | **постоянная строка состояния в правом нижнем углу** |
| Состояние сохранения | ⛔ | ⛔ | оранжевое «Есть несохранённые изменения» висит, пока правки не сохранены; зелёное «Расписание сохранено» гаснет через 6,5 с (остальные сообщения — 4,5 с) |
| Оформление надписей | — | — | один шрифт и размер для обеих надписей, различие **только в цвете** |
| Текущее время | ⛔ | ⛔ | дата, день недели и время **в формате выбранной локали** и с учётом переключателя 24h/12h |

**Почему это изменение.** Всплывающие уведомления в правом верхнем углу перекрывали переключатели
языка и формата времени и исчезали раньше, чем их успевали прочитать. Постоянная строка решает обе
задачи. Часы там же отвечают на вопрос «какое сейчас время на сервере» — именно по нему вычисляются
интервалы, что связано с примечанием о переходе на летнее время.

Примеры вывода часов:

```
ru, 24 ч →  Вторник, 8 сентября 2026 г.        14:26:34
en, 12 ч →  Tuesday, September 8, 2026          2:24:58 PM
```

## 8. Регулируемые панели — новое в v3

В v1 и v2 ширины боковых панелей были фиксированными. Это ломается на русской локали: подписи длиннее
английских, а названия расписаний и объектов в «Где используется» произвольной длины — текст обрезался.

- Перетаскиваемые разделители между списком и редактором и между редактором и панелью дня.
- Двойной клик — сброс к исходной ширине; `←`/`→` при фокусе с клавиатуры, с `Shift` — крупным шагом.
- Ограничения: список **200–460 px** (по умолчанию 268), панель дня **256–520 px** (по умолчанию 306),
  при этом редактору в центре **всегда гарантируется 520 px** — в узком окне панель упрётся раньше
  своего максимума.
- При изменении размера окна ширины пересчитываются, чтобы сетка не сплющилась.

## 9. Готовность к реализации

| | v1 | v2 | **v3** |
|---|---|---|---|
| Технология | внутренний DSL `<x-dc>` / `DCLogic` — не обычный HTML | работающее приложение | **один самодостаточный HTML-файл**, открывается двойным кликом, работает офлайн |
| Дизайн-система | ✅ штатные токены `--one-*` | ✅ та же система | ✅ CSS-переменные-аналоги `--one-*`, светлая и тёмная схемы |
| Контракт с backend | ⛔ | ✅ виден в DevTools | ✅ **аккордеон «Предпросмотр запроса к API»** — прототип работает как исполняемая спецификация |
| Импорт / экспорт JSON | ⛔ | ⛔ | ✅ тиражирование конфигурации между серверами |
| Тёмная тема | ✅ | 🟡 | ✅ |

Форма запроса, которую показывает v3:

```json
{ "modified_intervals": [ { "id": "s1",
    "added_intervals": [ { "start": { "day_of_week": 1, "hour": 9, "minute": 0, "second": 0 },
                           "length_seconds": 32400,
                           "period_seconds": 604800 } ],
    "modified_intervals": [], "removed_intervals": [] } ] }
```

## 10. Что из v1 и v2 сознательно не перенесено

| Решение | Причина |
|---|---|
| Двойной клик как способ **создать** интервал (v1) | Отдан протяжке; двойной клик теперь **открывает** блок в панели дня. |
| Модель «22:00–24:00 + 00:00–06:00» (v1) | Расходится с доменной моделью и API; заменена одним интервалом с переходом через полночь. |
| Дублирующие пресеты `weekend` / `always` (v1) | Отличались только набором дней; набор шаблонов переработан под реальные сценарии. |
| Фиксированный шаг привязки 15 мин (v1) | Добавлен выбор, включая 5 мин для точной подгонки. |
| Массовые операции по всей неделе без области действия (v2) | Слишком легко потерять работу; область действия задаётся чекбоксами дней. |
| Всплывающие уведомления в углу (v2) | Заменены строкой состояния — см. раздел 7. |
| Фиксированные ширины панелей (v1, v2) | Заменены регулируемыми разделителями — см. раздел 8. |

## 11. Что нужно сверить перед реализацией

1. **Имя корневого ключа payload.** В DevTools на скриншоте v2 виден `modify_intervals`, а v3
   показывает `modified_intervals`. Нужно зафиксировать одно имя — расхождение чисто в названии,
   но оно попадёт в контракт.
2. **`day_of_week` в `start`.** В наблюдаемом payload v2 внутри `start` были только `hour`, `minute`,
   `second`. v3 добавляет `day_of_week`, потому что иначе интервал невозможно привязать к дню недели.
   Требуется подтверждение, что сервер ожидает именно это поле, а не смещение от начала недели.
3. **`period_seconds` для непериодических интервалов.** v3 подставляет `604800` (неделя).
   Нужно проверить, что сервер трактует это как «однократно в неделю», а не как ошибку.
4. **Цикличные интервалы.** v3 передаёт длительность импульса как `pulse_seconds`. Поле в
   наблюдаемом контракте не встречалось — имя предположительное.
5. **Даты-исключения и праздники.** Функциональность взята из десктопа/PSIM; серверный контракт для
   неё в веб-API не наблюдался. Нужно решить, реализуется ли она на том же эндпоинте или отдельном.
6. **Figma-макет.** Доступ закрыт авторизацией, поэтому v1-эталон восстановлен по документации
   продукта. Если в макете есть блоки, не описанные здесь, их нужно сверить отдельно.
