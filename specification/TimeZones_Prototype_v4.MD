# Временные зоны / Time schedules — чем прототип v4 отличается от v3

**Продукт:** ITV/Axxon — Интеллект X / Axxon One / Axxon Next
**Раздел:** WEB-конфигуратор → Временные зоны / Time schedules
**Дата:** 08.09.2026
**Предмет сравнения:** `schedule_v4.html` против `schedule_v3.html`
**Причина появления v4:** устранение всех проблем, зафиксированных в `Efficiency_Analysis.MD`

---

## Коротко: три главных отличия

1. **Шаблон перестал быть неделей.** v3 умел описывать только семь строк, привязанных к дням недели.
   v4 добавляет второй тип шаблона — **цикл произвольной длины 2…31 суток** с привязкой первого дня
   цикла к календарной дате. Это единственный способ выразить 2/2, 3/3, 4/4, вахту 15/15 и
   чередование недель А/Б; в v3 они были невыразимы в принципе.
2. **Появился резолвер — единая точка вычисления графика.** Функция `effectiveOn(расписание, дата)`
   последовательно применяет **срок действия → исключение → список праздников → строку шаблона**
   и возвращает итоговый набор интервалов вместе с признаком, какое правило сработало. Из неё
   считается всё остальное: календарь, часы, пилюля «Активно сейчас» и payload. В v3 эти настройки
   сохранялись, но **ни на что не влияли** — это были дефекты №1 и №2.
3. **Результат стало можно проверить глазами.** Новый аккордеон «Проверка по календарю» показывает
   месяц, раскрашенный по итоговому графику, с полосой интервалов и часами в каждой ячейке.
   Без него сложные конфигурации из десятков исключений невозможно было ни проверить, ни защитить
   на приёмке.

## 1. Модель шаблона: неделя → цикл произвольной длины

Это отличие важнее всех остальных: оно меняет структуру данных, а не оформление.

| | **v3** | **v4** |
|---|---|---|
| Структура | `days: { Mon: [], Tue: [], … Sun: [] }` — ровно 7 именованных ключей | `pattern: { kind, len, anchor, days: [ [], … ] }` — массив из `len` строк |
| Тип шаблона | только недельный | переключатель **Неделя / Цикл** в новой панели над сеткой |
| Длина цикла | — | **2…31 суток**, поле ввода; при уменьшении лишние строки отбрасываются, при увеличении добавляются пустые |
| Привязка к календарю | жёстко по дням недели | поле **«Начало цикла»** — дата, на которую приходится день 1 |
| Подписи строк сетки | Понедельник … Воскресенье | «День 1» … «День N» + мелкой строкой **ближайшая дата**, когда эта строка выпадет |
| Сменные графики 2/2, 3/3, 4/4 | ⛔ невыразимы | ✅ готовые шаблоны и ручной ввод |
| Чередование недель А/Б | ⛔ | ✅ цикл 14 суток |
| Вахта 15/15 | ⛔ | ✅ цикл 30 суток |
| Скользящие выходные (4/1, 6/1) | ⛔ | ✅ цикл длиной, не кратной 7 |

**Что удалено.** Поле «Повторять каждые N дней» из раздела «Дополнительно» убрано целиком.
Оно было инертным (дефект №3) и, что важнее, **описывало механику, которая не выражает 2/2 даже
теоретически**: повтор одной и той же недели каждые N дней — это не цикл. Вместо него введён
честный редактор цикла.

**Что переиспользовано без изменений.** Сетка, рисование протяжкой, стирание, перетаскивание,
изменение длины за края, шаг привязки, undo/redo, инспектор строки — всё работает поверх цикла
ровно так же, как работало поверх недели. Меняется только число строк и их подписи.

**Набор шаблонов вырос с 8 до 15** и разделён в выпадающем списке на две группы:

| Недельные (как в v3) | Сменные циклы (новое) |
|---|---|
| Рабочие часы · Расширенный офис · Две смены · Ночи · Нерабочее время · Выходные · 24/7 · Цикличная выборка | 2/2 дневная (цикл 4) · 2/2 ночная (цикл 4) · 3/3 (цикл 6) · 4/4 (цикл 8) · 4/1 со скользящими выходными (цикл 5) · Вахта 15/15 (цикл 30) · Неделя А / неделя Б (цикл 14) |

Применение циклового шаблона к недельному расписанию запрашивает подтверждение с явным текстом:
«"2/2 дневная смена" — это цикл 4 суток. Применение переключит "Охрана" с недели на цикл 4 суток».

## 2. Резолвер: одна функция вместо трёх независимых расчётов

В v3 покрытие, «Активно сейчас» и payload считались тремя независимыми кусками кода, и **ни один
из них не смотрел на исключения**. В v4 они все вызывают резолвер.

```
effectiveOn(расписание, дата) →
    срок действия не подошёл      → { интервалы: [], правило: 'вне срока' }
    подошло исключение            → { интервалы: по режиму,  правило: 'исключение' }
    дата в списке праздников      → { интервалы: по режиму,  правило: 'праздник'  }
    иначе                         → { интервалы: строка N,   правило: 'шаблон'    }
```

| Что считается | v3 | **v4** |
|---|---|---|
| «Активно сейчас» | по недельному шаблону; расписание 24/7 с исключением «нерабочий на сегодня» показывало **«Активно сейчас»** | через резолвер: исключение и срок действия гасят пилюлю |
| Часы за период | сумма по 7 дням шаблона | сумма по шаблону **плюс** отдельная строка «N ч в этом месяце» с учётом всех переопределений |
| % покрытия | доля от 168 ч | доля от `длина цикла × 24 ч`, для цикла дополнительно показывается **среднее в неделю** |
| Раскраска календаря | — | целиком из резолвера |
| Payload | только недельная сетка | всё, что вернул бы резолвер (см. раздел 7) |

**Приоритет правил задан явно.** Исключение сильнее праздника: конкретная дата, введённая
руками, важнее общесерверного списка. Срок действия сильнее всего: за его пределами расписание
превращается в «без интервалов» независимо от исключений.

## 3. Проверка по календарю — новый раздел

| | v3 | **v4** |
|---|---|---|
| Представление месяца | ⛔ | ✅ аккордеон «Проверка по календарю», открыт по умолчанию |
| Содержимое ячейки | — | номер дня · мини-полоса интервалов · часы · буква сработавшего правила (`E` исключение, `H` праздник, `—` вне срока) |
| Раскраска | — | шаблон — белый, исключение — оранжевый, праздник — красный, вне срока действия — серый |
| Навигация | — | ‹ / › по месяцам, кнопка «Сегодня», обводка текущего дня |
| Итог месяца | — | пилюля «N ч в этом месяце» — **фактические** часы, а не по шаблону |
| Выбор дня | — | клик по дню показывает разбор: дата, какое правило сработало, сколько часов, и две кнопки — «Открыть строку шаблона» и «Создать исключение на эту дату» |

**Зачем это нужно.** В `Efficiency_Analysis.MD` сценарий «месяц конфигурируется практически каждый
день со своим графиком» был помечен как выполнимый ценой десятков строк исключений, которые
**невозможно проверить**. Календарь закрывает именно это: он показывает не то, что введено,
а то, что получилось. Кнопка «Создать исключение на эту дату» превращает его ещё и в способ ввода —
переопределить конкретный день можно, не переключаясь в таблицу.

## 4. Исключения: таблица → карточки

| | v3 | **v4** |
|---|---|---|
| Вёрстка | строка таблицы | карточка с двумя ярусами: даты и режим сверху, детали снизу |
| Интервалов на дату | **только один**, редактировался лишь первый | **сколько угодно**, кнопка «＋ интервал» и удаление каждого |
| Сокращённый день с перерывом (09–13 + 14–17) | ⛔ | ✅ |
| Фильтр по дням недели внутри диапазона | ⛔ | ✅ переключатели Пн…Вс: «с 16 по 20 ноября, но только Пн, Ср, Пт» |
| Режимов | 4 | **5**, добавлен «Как в другом расписании…» |
| Комбинация двух графиков (основной + корректирующий) | ⛔ | ✅ через режим «как в другом расписании» — на выбранные даты подставляется итог другого расписания |
| Сортировка | ⛔ хаотичный порядок ввода | ✅ хронологическая, пересортировка при каждом изменении даты |
| Пересечения диапазонов | ⛔ поведение не определено | ✅ значок ⚠ на обеих строках, подсветка карточки, подсказка «пересекается с N другими правилами» |
| Правило разрешения конфликта | ⛔ | ✅ **побеждает более узкий диапазон**, при равной ширине — последний по списку; результат виден в календаре |
| Дублирование строки | ⛔ | ✅ кнопка ⧉ — «размножить особую дату» без повторного ввода |
| Массовое удаление | ⛔ только по одной | ✅ «Очистить все» с подтверждением и указанием количества |

## 6. Бригады — новое в v4

Промышленный сменный учёт почти никогда не сводится к одному циклу: по одному и тому же
циклу 2/2 работают четыре бригады со сдвигом в сутки.

- Поля **«Бригад»** (1…8) и **«Сдвиг»** (в сутках внутри цикла) в панели над сеткой.
- Селектор **«Показать бригаду»** переключает, для какой бригады рисуются календарь, ближайшие
  даты у строк сетки и бейдж «СЕГОДНЯ». Это **предпросмотр**, а не правка: переключение не помечает
  расписание изменённым и не попадает в историю undo.
- Смещения бригад уходят в payload отдельным массивом `crews`.
- Демо-расписание «Охрана, бригады 2/2» настроено на 4 бригады со сдвигом 1 сутки.

## 7. Арифметика интервалов: две правки, меняющие результат

| | v3 | **v4** |
|---|---|---|
| Смежные интервалы | сливались молча: две смены **06:00–14:00 и 14:00–22:00 превращались в 06:00–22:00** при первой же правке дня | сливаются **только реально перекрывающиеся**; стыкующиеся сохраняются раздельно, граница смен переживает редактирование |
| Сообщение о слиянии | ⛔ | ✅ строка состояния: «2 перекрывающихся интервала слиты. Стыкующиеся интервалы сохранены раздельно» |
| Перенос через полночь | не ограничен: интервал 20:00 длиной 30 ч давал покрытие **26 ч** в одних календарных сутках | ограничен сутками — покрытие дня никогда не превышает 24 ч |

Первая правка — продуктовое решение в пользу трактовки «модель описывает смены», а не «модель
описывает покрытие». Оно соответствует и десктопу, и тому, как пользователи описывают графики вслух.

## 8. Payload: от недельной сетки к полному расписанию

В v3 предпросмотр запроса был честной «исполняемой спецификацией» только для недельной сетки:
добавление тридцати исключений не меняло его ни на байт. В v4 payload несёт расписание целиком.

| Блок | v3 | **v4** |
|---|---|---|
| Корневой ключ | `modified_intervals` | `modify_intervals` — имя, наблюдавшееся в DevTools (см. раздел 10) |
| Тип шаблона и длина | ⛔ | `pattern: { kind, length_days }` |
| Дата начала цикла | ⛔ | `pattern.anchor_date` |
| Привязка интервала | `start.day_of_week` | `day_of_week` для недели, **`day_of_cycle`** для цикла |
| `period_seconds` | всегда 604800 | `длина цикла × 86400`, для цикличных — период импульса |
| Бригады | ⛔ | `crews: [ { index, offset_days } ]` |
| Срок действия | ⛔ | `valid_from` / `valid_to` |
| Праздники | ⛔ | `holiday_list: { enabled, mode, same_as_day }` |
| Исключения | ⛔ | массив `exceptions` с диапазоном, флагом `yearly`, фильтром `weekdays`, режимом, ссылкой на строку или расписание, интервалами и комментарием |

Форма запроса, которую показывает v4 для циклового расписания:

```json
{ "modify_intervals": [ {
    "id": "s22",
    "pattern": { "kind": "cycle", "length_days": 4, "anchor_date": "2026-09-01" },
    "crews": [ { "index": 1, "offset_days": 0 }, { "index": 2, "offset_days": 1 },
               { "index": 3, "offset_days": 2 }, { "index": 4, "offset_days": 3 } ],
    "valid_from": null, "valid_to": null,
    "holiday_list": { "enabled": false, "mode": "none", "same_as_day": null },
    "added_intervals": [ { "start": { "day_of_cycle": 1, "hour": 8, "minute": 0, "second": 0 },
                           "length_seconds": 43200, "period_seconds": 345600 },
                         { "start": { "day_of_cycle": 2, "hour": 8, "minute": 0, "second": 0 },
                           "length_seconds": 43200, "period_seconds": 345600 } ],
    "modified_intervals": [], "removed_intervals": [],
    "exceptions": [ { "from": "2026-11-16", "to": "2026-11-20", "yearly": false,
                      "weekdays": [ 1, 3, 5 ], "mode": "sameAs", "same_as_day": 1,
                      "same_as_schedule": null, "intervals": [],
                      "comment": "Плановое обслуживание" } ] } ] }
```

## 9. Что осталось из v3 без изменений

Всё, что в анализе эффективности не вызвало нареканий, перенесено как есть:

рисование и стирание протяжкой · перетаскивание и изменение длины блоков · шаг привязки 5/15/30/60 мин ·
undo/redo до 60 шагов · клавиатурные сокращения · интервалы через полночь и цикличные интервалы ·
чекбоксы строк как область действия массовых операций · копирование строки с режимами «заменить» и
«добавить» · копирование одного интервала · инверсия · превью в списке расписаний · панель
«Где используется» · подтверждения разрушающих действий · строка состояния с часами · регулируемые
разделители панелей · светлая и тёмная темы · импорт/экспорт JSON · один самодостаточный HTML-файл
без внешних зависимостей.

Локализация тоже сохранена и расширена: **353 ключа** в каждой из двух локалей против 274 в v3,
с теми же правилами русских числительных и падежных форм. Идентичность состава ключей проверяется
автоматически.

Объём: **2311 строк / 151 КБ** против 1671 строки / 112 КБ в v3.

## 10. Соответствие проблемам из `Efficiency_Analysis.MD`

### Дефекты

| № | Дефект v3 | Как закрыт в v4 |
|:--:|---|---|
| 1 | Исключения, срок действия и периодичность отсутствуют в payload | Раздел 8 — payload несёт расписание целиком |
| 2 | Расчёты игнорируют исключения | Раздел 2 — все расчёты идут через резолвер |
| 3 | Поле «Повторять каждые N дней» инертно и описано неверно | Раздел 1 — удалено, заменено редактором цикла |
| 4 | Перенос через полночь не ограничен сутками | Раздел 7 — покрытие дня ограничено 24 ч |
| 5 | Смежные интервалы сливаются без предупреждения | Раздел 7 — сливаются только перекрывающиеся, о слиянии сообщается |
| 6 | Таблица исключений не сортируется по дате | Раздел 4 — хронологическая сортировка |
| 7 | Нет проверки пересечения диапазонов исключений | Раздел 4 — значок ⚠ и явное правило «побеждает более узкий» |

### Рекомендации

| Приоритет | Рекомендация | Где закрыта |
|:--:|---|---|
| P0 | Довести исключения, срок действия и периодичность до payload и до расчётов | Разделы 2 и 8 |
| P0 | Заменить «Повторять каждые N дней» на редактор цикла произвольной длины | Раздел 1 |
| P1 | Календарное представление на месяц с раскраской по итоговому графику | Раздел 3 |
| P1 | Разрешить несколько интервалов на дату-исключение | Раздел 4 |
| P1 | Ограничить перенос через полночь сутками | Раздел 7 |
| P2 | Сортировка исключений, проверка пересечений, копирование и массовое удаление | Раздел 4 |
| P2 | Не сливать смежные интервалы молча | Раздел 7 |
| P3 | Понятие «бригада» и сдвиг цикла между бригадами | Раздел 6 |

### Сценарии, помеченные в анализе как невыполнимые

| Сценарий | Как выполняется в v4 |
|---|---|
| Сменные графики 2/2, 3/3, 4/4 | Готовый цикловый шаблон либо цикл нужной длины вручную |
| Вахта 15/15 | Шаблон «Вахта 15/15», цикл 30 суток |
| Чередование недель А/Б | Шаблон «Неделя А / неделя Б», цикл 14 суток |
| Скользящие выходные при 5/2 | Цикл длиной, не кратной 7 (4/1, 6/1) |
| Несколько бригад со сдвигом | Поля «Бригад» и «Сдвиг» + селектор предпросмотра |
| Исключение на набор дней недели | Фильтр Пн…Вс внутри диапазона исключения |
| Приоритет при пересечении исключений | Явное правило + предупреждение + проверка по календарю |
| Проверить месяц глазами | Аккордеон «Проверка по календарю» |
| Размножить особую дату | Кнопка ⧉ на карточке исключения |
| Массовое удаление исключений | Кнопка «Очистить все» |
| Сезонный график | Срок действия теперь реально применяется |
| Сокращённый день с перерывом | Несколько интервалов на дату-исключение |
| Комбинация двух расписаний | Режим исключения «как в другом расписании» |

## 11. Что нужно сверить перед реализацией

Пункты 1–4 и 6 из `TimeZones_Prototype_v3.MD` остаются в силе. Изменилось и добавилось следующее.

1. **Имя корневого ключа.** v4 перешёл на `modify_intervals` — имя, наблюдавшееся в DevTools.
   Расхождение с v3 (`modified_intervals`) устранено в пользу наблюдаемого варианта,
   но подтверждение от backend всё ещё требуется.
2. **`day_of_cycle`.** Для цикловых расписаний интервал привязывается к номеру дня цикла, а не к дню
   недели. Поле предположительное — в наблюдаемом контракте циклов не было. Нужно решить, поддерживает
   ли сервер циклы вообще или их придётся разворачивать в набор дат на стороне конфигуратора.
3. **`anchor_date`.** Без даты привязки цикл не определён. Требуется подтверждение, что сервер хранит
   её вместе с расписанием, а не вычисляет от даты создания.
4. **Бригады.** Массив `crews` со смещениями — предложение прототипа. Альтернатива — заводить
   отдельное расписание на каждую бригаду; это проще для backend, но умножает число объектов на четыре
   и рассинхронизируется при правке цикла. Решение продуктовое.
5. **Исключения и праздники в API.** Контракт по-прежнему не наблюдался. v4 предлагает конкретную
   форму (раздел 8); её нужно либо принять, либо заменить на серверную.
6. **Общесерверный список праздников.** Прототип считает его глобальным объектом, а правило поведения —
   свойством расписания. Нужно подтвердить, что список действительно один на сервер, а не на домен
   или на пользователя.
7. **Ширина цикла.** Ограничение 2…31 суток выбрано из соображений вменяемости интерфейса
   (31 строка сетки уже требует прокрутки). Если реальны вахты 60/60, потребуется другое
   представление сетки, а не только снятие ограничения.

## 12. Проверка

Прототип прогоняется автоматическим набором из **90 утверждений** без браузера: резолвер
(исключения, праздники, срок действия, фильтр по дням недели), арифметика интервалов (слияние,
ограничение переноса), циклы и все цикловые шаблоны, бригадные смещения, обнаружение пересечений,
месячные итоги, полнота payload, соответствие состава ключей локализации и полный ререндер каждого
демо-расписания в обоих языках со всеми раскрытыми панелями.
